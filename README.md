# Elfia Arcen — lean static site

A stripped-down, information-only rebuild of the Elfia website, focused on the
next edition: **Elfia Arcen, 19 & 20 September 2026** at the Kasteeltuinen Arcen.
No ticketing, no JavaScript, no animation — just the practical information.

## Hosting

Served at **https://3w3.nl/elfia**

## What's here

Static HTML, one shared stylesheet, one image. Dutch is the default; English lives
under `/en/`. Every page has an EN/NL toggle in the nav.

Total: 23 pages + 2 calendar files, ~600 KB including the map image (`vendors.html` is the largest page at 38 KB — 110 stalls with descriptions). First paint of the home page is
~5 KB gzipped over 2 requests (plus the lazy-loaded map).

The pages are generated by a build script (kept in the working scratch, not deployed)
that reads content snapshots extracted from the original site. To change copy, edit the
build inputs and regenerate — don't hand-edit the HTML.

**Exception:** the line-up upgrade of 26 Aug 2026 (category filter, Music A–Z, calendar
files) was applied directly to `lineup.html` / `en/lineup.html`, because the build script
was not in the repo. Fold it back into the build inputs before the next regeneration, or
the changes will be overwritten.

## Caterers

There is no catering endpoint. The caterer list lives **inside `programme`**: each realm
under `resultProgramme[Arcen].highlightImage` (where `categoryType == "realms"`) carries a
`shops` array — the food stalls — next to its `exhibitors` array. 14 shops across 5 realms:
Melody Market, Willow Way, Odin's Vale, Folk Faire, The Copper Quarter.

Each shop has `name`, `description`, `coverImage` and `labels`, where the labels are drawn
from exactly four values: Vegan, Vegetarian, Halal, Gluten Free. **These are dietary
indications, not an allergen declaration** — only gluten is an allergen among them, and 5 of
the 14 stalls carry no labels at all. `food.html` says so explicitly rather than implying the
list is complete; the allergen section points visitors at the stall and at the medical/dietary
exemption in `policy.html#food`.

Every generated page is built from `build/programme.json` by the scripts in `build/`.
One command rebuilds the lot: `sh build/build-all.sh`. See `CLAUDE.md` for the full
picture, including the traps.

## Calendar files

**Bandits Creek and Elfia Treasures are excluded from both `.ics` files** on purpose
(`EXCLUDED_STAGES` in `build/make-ics.py`): a roaming all-day act, quarter-hour
line-dancing slots and signing sessions are calendar clutter rather than things you plan a
day around. They do appear on the line-up page.

`elfia-2026-muziek.ics` (music only) and `elfia-2026-programma.ics` (everything) are
plain iCalendar 2.0, one `VEVENT` per programme item, all timed with an embedded
`Europe/Amsterdam` `VTIMEZONE` so imports are correct from any time zone. `UID`s are
derived from date + stage + start time + act name, so re-importing an updated file
replaces events rather than duplicating them. No alarms are set.

Both files are generated from the two line-up pages themselves — the parser reads the
`.tt-list` rows, so the calendars can never drift from what the page shows. Regenerate
whenever the timetable changes.

## Data source

Content was extracted once from the original site and its back-office API, then baked
into static HTML. The site does **not** call any API at runtime.

The original event data lives behind a back-office API at
`https://bo-elfia.lusolab.com/api/` — POST, form-encoded (`lang=en|nl|de`), JSON back,
Cloudflare-fronted, CORS restricted to `https://elfia.nl`. Known endpoints:

| Endpoint | Contents | `lang` localizes? |
|---|---|---|
| `programme` | Timetable (5 stages × 2 days), realms, highlights, **caterers, exhibitors** | no |
| `faqList` | 61 Q&As in 12 categories | yes |
| `news` | 36 news articles (title, HTML body, image) | no |
| `header` | Live announcement banner | no |
| `termsAndConditions` | Full T&C text | no |
| `winnerList` | Quest-game winners — real names; **do not republish** | — |
| `getInvolved` | Application categories + form links. Needs `?programmeId=1` (Arcen) — without it: `{"code":104,"msg":"Missing Parameter."}` | no |
| `enquiry` | Contact-form submit — **write endpoint, never called** | — |
| `chatBot` | Site chatbot backend — **write endpoint, never called** | — |

All six documented endpoints still return 200. `getInvolved`, `enquiry` and `chatBot` were
found by reading elfia.com's own scripts rather than by guessing; blind probes for
`catering`, `vendors`, `exhibitors`, `events`, `locations`, `realms`, `tickets` etc. all 404.
`GET` on any endpoint returns `405 Method Not Allowed` — it is POST-only, so no API URL is
linkable.

### Data in the payloads that nothing on either site uses

| Where | What | Count |
|---|---|---|
| `programme` → realm `shops[]` | Caterers — **now used**, see `food.html` | 19 |
| `programme` → realm `exhibitors[]` | Traders — **now used**, see `vendors.html`. All have a description and an image, 1 (`Het Elfenbankje`) has a link | 124 |
| `programme` → `highlightImage[categoryType=highlight]` | Act/guest highlights | 36 |
| `programme` → `highlightImage[categoryType=realms]` | Realms | 20 |
| `programme` → `highlightImage[categoryType=workshop]` | Academy workshops | 5 |
| `news` | Articles: title, HTML body, image (no date field) | 36 |
| `header` | Live ticket banner | 1 |

elfia.com fetches `shops` and `exhibitors` with every programme call but **renders neither** —
no script on the site references either field. Both are now surfaced here, on `food.html` and
`vendors.html`, built by `make-food.py` and `make-vendors.py` from JSON snapshots.

### Provenance notice

`lineup.html`, `food.html` and `vendors.html` each carry a `.srcnote` block in the page head
saying the data is taken unedited from the API, that Elfia publishes none of it themselves so
there is nothing to check it against, and that this is not an official Elfia publication. The
two generators emit it; on the line-up it is hand-placed. Keep it on any future page built
from API data.

Snapshots were taken on 2026-08-26. Anything sourced from the API is point-in-time and
can go stale (e.g. the announcement banner, sold-out status).
